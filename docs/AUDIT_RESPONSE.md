# Audit Response & Remediation Matrix

This document provides a comprehensive, item-by-item response to the independent re-audit of commit `ac27a80` for the Ascon AEAD + Hash Secure-Boot SoC project (`Ascon-AEAD-and-HASH`).

Every finding is documented with:
1. **Issue Identified:** Exact description of what was wrong.
2. **Action Taken:** Code, testbench, script, or documentation modifications applied.
3. **Verification Command:** The exact tool command executed.
4. **Evidence File:** Path to the fresh, non-stale log or report artifact.
5. **Real Result:** The actual measured empirical result.

---

## 1. Remediation Matrix

### Subsequent Audit Closure & Reconciliation (November 6–11, 2026)

Following the initial November 5, 2026 remediation pass below (preserved as historical record for commit `ac27a80`), later passes closed the open S-box optimization items (Berkeley ESPRESSO `-Dexact`, Brayton-McMullen algebraic kernel extraction, and shared ROBDD synthesis under `tools/sbox_opt/`), re-ran full 7-variant engine synthesis, ran the 39/39 XSim regression, generated both baseline (`build/top_bringup.bit`, WNS `+1.510 ns`, Fmax `117.79 MHz`) and ILA (`build/top_bringup_ila.bit`, WNS `+1.042 ns`) bitstreams, and recorded partial physical validation on a Digilent Zybo Z7-10 board (`SW0=0` normal boot and `SW0=1` refusal LEDs + steady-state `-trigger_now` ILA CSVs). Obsolete pre-remediation helper scripts (`reproduce_sbox_espresso.py` and `sbox5_espresso_rtl_as_pla.pla`) were removed after real ESPRESSO output was committed in [`results/synthesis/espresso_raw_output.pla`](../results/synthesis/espresso_raw_output.pla).

## 2. Items Explicitly Not Done or Partial (Honest Status)

In compliance with Non-Negotiable Rule 4 ("If something cannot be done, say so in the docs. An honest 'NOT DONE' is better than a false 'DONE'"):

1. **Hardware Side-Channel Masking in RTL:**
   - **Status:** **NOT DONE**
   - **Reason:** Masked Ascon (e.g., 2-share or 3-share DOM/TI as analyzed by Groß et al., TCHES 2018) requires multi-cycle affine S-box sharing, PRNG/TRNG fresh randomness injection infrastructure (~128–320 bits/cycle), and pipeline register duplication. The current project scope focuses on unmasked lightweight implementations. Qualitative analysis is provided in [`docs/research_review.md`](research_review.md).
2. **Physical On-Board Hardware Testing (Zybo Z7-10):**
   - **Status:** **PARTIAL** (Normal Boot & `SW0` Byte-Flip Refusal Logged; Remaining Checks Pending)
   - **Completed:** Bitstreams generated for baseline (`build/top_bringup.bit`, WNS `+1.510 ns`, SHA256 `79cef83aa8ec05081a92359999da7ca5b3f13d77ae5bee70073c39f3b8862c86`, [`results/board/bitstream_build.log`](../results/board/bitstream_build.log)) and ILA (`build/top_bringup_ila.bit`, WNS `+1.042 ns`, [`results/timing/timing_bringup_ila.txt`](../results/timing/timing_bringup_ila.txt)). On a physical Digilent Zybo Z7-10 (`xc7z010_1`), normal boot (`LD0..3 = 4'b1111`, RGB `LD6` = Green) and live `SW0` byte-flip refusal (`LD0..3 = 4'b1010`, RGB `LD6` = Red) were visually verified and sampled in steady state via `-trigger_now` ILA captures ([`ila_capture_normal_boot.csv`](../results/board/ila_traces/ila_capture_normal_boot.csv), [`ila_capture_fault_injection.csv`](../results/board/ila_traces/ila_capture_fault_injection.csv)).
   - **Pending:** Rising-edge triggered transient boot ILA capture (`capture_ila.tcl normal` / `fault`), recorded `SW1` tamper switch test, physical oscilloscope/counter latency measurement, and on-board KAT execution (not included in `top_bringup_board` BRAM image). See [`results/board/HARDWARE_RUNBOOK.md`](../results/board/HARDWARE_RUNBOOK.md) and [`results/board/ila_verification_report.md`](../results/board/ila_verification_report.md).
