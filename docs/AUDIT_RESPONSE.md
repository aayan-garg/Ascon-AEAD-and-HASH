# Audit Response & Remediation Matrix

This document provides a comprehensive, item-by-item response to the independent re-audit of commit `ac27a80` for the Ascon AEAD + Hash Secure-Boot SoC project (`Ascon-AEAD-and-HASH`).

Every finding is documented with:
1. **Issue Identified:** Exact description of what was wrong.
2. **Action Taken:** Code, testbench, script, or documentation modifications applied.
3. **Verification Command:** The exact tool command executed.
4. **Evidence File:** Path to the fresh, non-stale log or report artifact.
5. **Real Result:** The actual measured empirical result.

## 2. Items Explicitly Not Done (Honest Status)

In compliance with Non-Negotiable Rule 4 ("If something cannot be done, say so in the docs. An honest 'NOT DONE' is better than a false 'DONE'"):

1. **Hardware Side-Channel Masking in RTL:**
   - **Status:** **NOT DONE**
   - **Reason:** Masked Ascon (e.g., 2-share or 3-share DOM/TI as analyzed by Groß et al., TCHES 2018) requires multi-cycle affine S-box sharing, PRNG/TRNG fresh randomness injection infrastructure (~128–320 bits/cycle), and pipeline register duplication. The current project scope is focused on unmasked ASIC/FPGA lightweight implementations. Qualitative analysis is provided in `docs/research_review.md`.
2. **Physical On-Board Hardware Testing (Zybo Z7-10 Board Execution):**
   - **Status:** **OUT OF SCOPE**
   - **Reason:** Physical hardware attachment and JTAG cable flashing are excluded per project instructions ("Hardware (on-board) steps are out of scope. Do not claim any board result"). Bitstream generation was successfully completed (`build/top_bringup.bit`, SHA256 `79cef83aa8ec05081a92359999da7ca5b3f13d77ae5bee70073c39f3b8862c86`, WNS +1.510 ns; build log recorded in [`results/board/bitstream_build.log`](../results/board/bitstream_build.log)). Constraints ([`board/zybo_z7_10.xdc`](../board/zybo_z7_10.xdc)), programming scripts ([`scripts/program_board.tcl`](../scripts/program_board.tcl)), and test runbooks ([`results/board/HARDWARE_RUNBOOK.md`](../results/board/HARDWARE_RUNBOOK.md)) are provided for future physical deployment.
